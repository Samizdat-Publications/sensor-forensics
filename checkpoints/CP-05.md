# CP-05: The app

Date: 11/02/2026
Milestone: M4
Commit / tag: see `git show cp-05` / cp-05 (tagged after the independent check)

## Accomplished

- A local web app (`app/`, three.js 0.170.0 vendored with its license, ES modules, no bundler) with five views for GIMBAL, GOFAST and FLIR1:
  1. **Cockpit:** the original frame beside a three.js re-render of what each hypothesis predicts the pod saw, with Difference and Blink modes. The original plays as an image sequence keyed by frame index (never `<video>` seeking), so the two sides always show the same frame. A strip reports the frame-lock error for this frame and for the whole clip.
  2. **God's-eye:** the jet's track, the line-of-sight fan, and each hypothesis's fitted path, with a range slider.
  3. **Range explorer:** speed, altitude, peak acceleration and sight-line misfit as functions of assumed range, per hypothesis, with reference lines (balloon drift, 1 g, 9 g, Mach 1).
  4. **Compare analyses:** Sitrec, Peings and von Rennenkampff 2023, and this lab, side by side.
  5. **Evidence ledger:** every number with its source frame, method and confidence. Clicking a row opens that frame. A testimony-weight slider rescores live from the per-criterion log-likelihoods, and a physics-only total is always shown beside the testimony-weighted one (D-011).
- Fixed while reviewing the screenshots: the ledger's second totals column used to rescore the stored fits with the excluded criteria added back, which gave different numbers from the CP-04 refit (H-WIT at 0.35 deg: -261 / -479 against 35.3 / -22.6). It now shows the scorer's own refit without exclusions, the same numbers as the results pages; the add-back button remains as a live what-if and is labeled as a rescore.
- Also fixed while reviewing the recordings: the cockpit said "Rotation: not scored for this case" on FLIR1 frames outside its rotation series; it now says "not scored at this frame" where the case scores rotation elsewhere. The rail's "Read first" list now also shows the sensitivities that change the leader (the refit without exclusions; the nearest rotation-noise crossover on each side of the data-only value, within a factor of 2), the same rule the case-file export uses; FLIR1 shows "above 12.75 deg H-ART leads".
- App data rebuilt from the CP-04 results (`tools/build_app_data.py`); the client totals and the client geometry equal the Python numbers (node parity tests, now for all three videos).
- The 60-second GIMBAL recording, captured frame by frame (`tools/record_gimbal.py`).

## Frame lock (median pixel error over the clip, 640 x 480 video pixels)

| Video | Object position | Horizon line | Notes |
|---|---|---|---|
| GIMBAL (both fields of view) | 1.86 px (1031 frames) | 2.1 to 2.5 px for every hypothesis except H-CLOSE (5.0 to 5.8 px) (995 frames) | Horizon measured from the cloud-deck motion direction |
| GOFAST | 1.41 px (771 frames) | n/a | Looks down at the sea: no measured horizon |
| FLIR1 | 5.8 px (1655 frames) | n/a | Featureless sky; small 352 x 264 copy |

The object error is the same for every hypothesis because the pod holds the object near the centre and every hypothesis predicts the same sight line there; it measures how well the pod model places the object, not which hypothesis is right. The horizon error does depend on the hypothesis (through the fitted jet pitch and the range), and only the close-object model misses it clearly.

## Known issues / debt

- The re-render shows the object as a lit ellipse sized and rolled by each hypothesis; it is a model of what the pod should see, not a photographic simulation of the infrared scene (no clouds or sea in the render).
- FLIR1's frame lock is looser (5.8 px) because the object is small and low contrast in the 352 x 264 copy.
- The recording shows one fit (H-BAL, testimony-weighted, 0.35 deg); every other fit can be viewed in the app.
